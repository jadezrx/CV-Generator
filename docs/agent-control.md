# Agent control

**Instruction — `post-implement-check`** (`.claude/skills/post-implement-check/SKILL.md`) se déclenche quand une session signale qu'un ticket est fini ("je pense qu'on peut clore ça", "issue #N est bouclée") : il vérifie que le commit est poussé et l'issue fermée, sauf pour tout ce qui touche l'authentification ou le routage public (`/manage`), où il commit localement seulement et attend une confirmation explicite. Testé positif sur l'issue #11 (déclenché sur une formulation naturelle, a découvert et fermé un bug déjà corrigé) et négatif sur une question purement technique sans rapport ("comment marche /manage") — aucun déclenchement, comme attendu. Élagué de 4 lignes après un test en session fraîche montrant qu'elles ne changeaient rien au comportement.

**Enforcement — `block-secrets.py`** (`.claude/hooks/block-secrets.py`, hook PreToolUse sur `Bash|Write|Edit`) bloque toute écriture ou tout commit contenant un motif de secret (mot de passe/clé en dur, token GitHub/AWS, clé privée) ou touchant un fichier `.env`. Une instruction ne suffisait pas ici parce qu'un secret poussé une seule fois reste dans l'historique git pour toujours, même supprimé ensuite dans un commit suivant — contrairement à un ticket mal formulé ou un push oublié, cette erreur-là n'est pas réversible après coup. Testé en conditions réelles : le blocage empêche effectivement l'écriture (fichier absent du disque après tentative) et le staging (`git status`/`git diff --cached` vides après tentative), pas seulement un message d'erreur affiché sans effet. Le hook a lui-même produit un faux positif en conditions réelles : il a bloqué la documentation citant littéralement le secret de test utilisé pour le prouver, puisque la citation reproduisait le pattern qu'il détecte — corrigé en reformulant la preuve en prose, sans toucher au hook.
